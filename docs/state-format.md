# 記事状態とロックの形式

この文書は、バッチが S3 に置く記事状態（`posts.json`）と実行ロックの形式、それを読み書きするときの決まりを定める。今の実装は Go（`batch/`。2026-11-28 までは Ruby の実装）。別の実装を入れるときも、同じファイルを読み書きできるようにこの決まりに従い、ここに書いていない挙動を当てにしない。運用の手順は `flow.md` にある。

## キー

バケットは `prpr-antena`。キーは `batch/internal/store` の `StateKey` と `LockKey` が `ANTENA_PREFIX`（ページの prefix）から決める。

| prefix | 記事状態 | ロック | ページ |
| --- | --- | --- | --- |
| 空（本番） | `state/posts.json` | `locks/antena-run.lock` | `index.html` など |
| `<p>`（shadow） | `state/<p>/posts.json` | `locks/<p>/antena-run.lock` | `<p>/index.html` など |

- prefix の前後の `/` は落とす。指定しないときの prefix は `migration-preview`
- prefix が違えば、記事状態とロックは別のものになる。shadow の実行は本番の記事状態を読まず、書かず、本番とロックを取り合わない
- `state/` と `locks/` は必ずキーの先頭に置く。バケットポリシーの `HideMigrationState` が `state/*` と `locks/*` をサイトから読めなくしているのは、この位置に限られる（`flow.md`「記事状態の置き場」）

## posts.json

UTF-8 の JSON。書くときは次の形にする。

```json
{
  "schema_version": 1,
  "exported_at": "2026-11-27T12:30:41.123456Z",
  "posts": [
    {
      "id": 512,
      "site_id": 7,
      "title": "記事の題",
      "url": "https://example.com/archives/1.html",
      "summary": "フィードの要約（そのまま）",
      "content": "<p>本文 <img src=\"https://example.com/a.jpg\"></p>",
      "published_at": "2026-11-27T12:10:00.000000Z",
      "created_at": "2026-11-27T12:30:40.654321Z",
      "updated_at": "2026-11-27T12:30:40.654321Z"
    }
  ]
}
```

読むとき:

- 最上位が配列なら、それを `posts` として読む
- `schema_version` は読まない。形を変えるときは、読む側を先に両方の形へ対応させてから書く側を変える
- `id`・`site_id`・`created_at` は必須。どれかが無いか空、`id`・`site_id` が整数として読めない、日時が読めないときは、ファイル全体を読めないものとして扱う
- `title` が無いときは `name` を題として読む（以前の形）
- 日時は ISO 8601 で書く。空文字列と `null` は値なしにする

各項目:

| 項目 | 内容 |
| --- | --- |
| `id` | 整数。ファイルの中で記事ごとに一意。新しい記事に、今ある最大の `id` + 1 から振る（間引いた記事の `id` は、また振られることがある）。ページはサイトごとの一覧と「直近2日」を `id` の降順で並べるので、取り込んだ順に大きくする |
| `site_id` | `config/sites.yml` の `sites[].id`。無効にしたサイト（`enable: false`）も含め、`sites.yml` に在る id でなければならない。無い id の記事が1件でもあると実行は失敗する（サイトを `sites.yml` から消すときは、先にそのサイトの記事を消す） |
| `title` / `url` / `summary` | フィードの項目のまま。`summary` は `null` でよい |
| `content` | フィードの本文（無ければ要約）から広告・関連記事などを取り除いた HTML。読む側が使うのは、この中の `<img>` だけ（サイトのページの画像）。Go は取り除いた要素を切り取っただけの元の HTML を書く（前の Ruby の実装は Nokogiri の `to_html` で、HTML 文書の形だった。どちらから取り出した `<img>` も同じバイトになる） |
| `published_at` | フィードの公開日時（UTC。Feedjira が UTC に直す）。無ければ `null` |
| `created_at` / `updated_at` | 取り込んだ日時（UTC）。ページの時刻と古い記事の間引きは `created_at` で決める |

`posts` の並びに意味は無い。ページはどれも `id` か `created_at` で並べ直す。

## 1回の実行で記事状態にすること

1. ロックを取る。取れなければ何も書かずに終える
2. 記事状態を読む。キーが無いときだけ WARN を出して空から始める。権限エラー・壊れた JSON など、それ以外の失敗では実行を止める（今ある記事を空で上書きしないため）
3. 有効なサイトを `id` の昇順に回り、フィードの順に新しい記事を足す。今ある記事（全サイト）と URL か題が同じものは足さない。公開日時が未来のものと URL の無いものも足さない。1つのサイトの取得に失敗しても、そのサイトを WARN で飛ばして続ける
4. 古い記事を間引く。記事が50件を超えるサイト（無効のサイトも含む）では、`created_at` が5日より前の記事を全部消す。50件以下のサイトでは消さない
5. 記事状態を書く。続けてページを書く（ページの書き込みが失敗しても、次の実行が同じ記事状態から書き直せる順）
6. ロックを消す

## ロック

中身は次の JSON。`token` は実行ごとの UUID、`started_at` は取った日時（UTC）。

```json
{"token": "3f0c…", "started_at": "2026-11-27T12:30:00.000000Z"}
```

取り方:

1. `If-None-Match: *` を付けて PUT する。通れば取れた
2. 409・412 なら今のロックを読む。それ以外の失敗（権限エラー・通信の失敗など）では実行を失敗にする。`token` が自分のものなら取れた（応答が失われた PUT を SDK が送り直した場合）
3. 409 だったとき、またはロックが読む前に消えていたときは、2回まで 1 からやり直す
4. `started_at` から1時間（`store.DefaultStaleAfter`）を過ぎていれば、止められた実行の残したロックとみなして奪う。奪うときは、読んだときの ETag を `If-Match` に付けて PUT し直す。ETag が読めなかったときは奪わない。`started_at` が読めないもの、中身が JSON のオブジェクトでないものも、過ぎたものとして扱う。奪う PUT が 404・409・412 なら別の実行が先に奪ったので、読み直す
5. 奪えなかったとき、まだ1時間たっていないときは、WARN（`antena skipped`）を出して何も書かずに終える

消し方: 読んだロックの `token` が自分のものなら消す。自分のものでなければ（奪われていれば）消さない。

ジョブの task-timeout（`release.yml` の 1800 秒）は、ロックを奪えるまでの1時間より短くしておく。実行中のタスクが Cloud Run に止められてからでないと、別の実行がそのロックを奪えないようにするため。

## 前の Ruby の実装との違い

Go の実装（`batch/`）は、前の Ruby の実装（2026-11-28 まで本番）と同じ記事・同じページを作るように作った。比べた答えは `batch/README.md`。次の場合だけ結果が違う（記録として残す）。

- フィードの形式: Go が読むのは RSS と RDF（Feedjira の RSS・ITunesRSS・RSSFeedBurner と同じ読み方）だけ。Atom と JSON Feed は、読めない形式としてそのサイトを WARN で飛ばす（Ruby は読む）。今の有効なサイトは全部 RSS か RDF
- `<guid/>` だけで `<link>` が無い記事: Ruby は URL を `no_buffer` という文字列にして取り込む（sax-machine の値の無い要素の扱い）。Go は URL が無いものとして捨てる
- Shift_JIS などの UTF-8 でないフィード: 文字の変換表が違う（Ruby は libxml2 の iconv、Go は WHATWG の表）。波ダッシュなど一部の文字が別の文字になる。文字コードの名前は、Go は WHATWG の名前と CP932・Windows-31J・SJIS などの別名を読み、それ以外は読めない（Ruby は iconv が知っている名前を読む）。ISO-8859-1 と US-ASCII は libxml2 と同じに変換する（0x80 以上のバイトは、Latin-1 ではその番号の文字、US-ASCII では変換できないバイト）
- 宣言した文字コードで変換できないバイトがあるとき: Go はそのフィードの記事を全部捨てる。Ruby も小さいフィードでは全部を失う。大きいフィードでは、そのバイトより前の記事は残ることもある
- ログ: Ruby は読めない日時に Feedjira の WARN を標準出力へ出す。Go は出さない。取得の失敗の WARN に出る種類の名前も違う（Ruby はクラス名、Go は Go の型名）
- フィードの日時: Ruby は `DateTime.parse` で、ほとんどの書き方を読む。Go は RFC 822・RFC 1123・ISO 8601 の書き方と、よく使うタイムゾーン名（JST・GMT・EST など）だけを読む。読めない日時は、どちらも値なしにする
- 本文の掃除で、閉じていない要素（`<p class="kijinai">` の後に `</p>` が無い）: libxml2 は次のブロックで閉じたとみなして、そこまでを消す。Go は終わりのタグか本文の終わりまでを消す
- 本文に値の無い属性（`<img ismap>`）があっても、どちらも名前だけを書き出す

## 別の実装を本番へ入れるとき

1. 別の実装を、prefix `migration-preview` で動かす。記事状態は `state/migration-preview/posts.json` になり、本番の記事状態に触れない。ページはライフサイクルで1日後に消えるので、片付けが要らない（別の prefix を使うなら、終わった後にページと `state/<prefix>/` を消す）。Go の実装を手元で prefix を指定せずに動かすときもこの prefix になるので、shadow の間は手で動かさない
2. 本番と同じ記事から始めて比べたいなら、始める前に `state/posts.json` を `state/migration-preview/posts.json` へコピーする。コピーしないと空から始まり、「直近2日」が揃うまで2日ほどかかる
3. 切り替えるときは、別の実装の prefix を空にする。本番と同じ `state/posts.json` とロックを使うので、旧い実装と同時に動いても、ロックで片方が飛ばされる。旧い実装の Scheduler を止めてから、新しい方の Scheduler を動かす
